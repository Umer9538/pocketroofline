PocketRoofline · station 01 · iPhone 13 (A15 Bionic)

LLM inference measured on a phone, not an edge board.

RooflineBench characterised on-device inference across desktop GPUs, an M1 Pro, a Jetson and a Raspberry Pi — no phones. This extends the same roofline methodology to smartphone silicon, with every repeat retained, thermal state recorded, and the matrix re-run on every OS and runtime update. Thermal collapse on phones has been measured independently (arXiv:2603.23640, iPhone 16 Pro, −41.5% over 20 runs); what this adds is the roofline placement, a mains-powered control and the open per-build record.

Station 01 is the iPhone 13 whose figures follow. Also measured: station 02 · iPhone 15 Plus (A16 Bionic), further down, with its caveats up front.

38%

Peak decode (42.8 tok/s, short prompts) overstates sustained decode (30.9 tok/s, after 5 consecutive long generations) by this much. Quoted phone-inference numbers are peak numbers.

Where this sits on the roofline

Single-stream decode reads every weight once per token, so decode throughput converts directly into achieved memory bandwidth (0.636 GB of weights per token). That places this workload firmly in the memory-bound region — which is why decode, not prefill, is what thermal throttling destroys.

Read the achieved column instead: the phone extracts a higher fraction of its memory system than the laptop does — it is simply working against a much smaller ceiling, and thermal throttling then takes away roughly a quarter of what it had.

PocketRoofline · station 02

iPhone 15 Plus (A16 Bionic, 6 GB)

iOS 27.0 (24A437), captured 2026-10-05 with the PocketRoofline app 1.0 (1), on the same model file, regimes and llama.cpp commit as station 01. Short-generation decode (SISO) averaged 65.16 tok/s (sd 0.52), which reads weights at 41.4 GB/s: 91% of this phone's measured ceiling (45.3 GB/s, Headroom probe). Read the caveats below before using any figure from this phone.

Caveats, which apply to every figure in this section:

  1. Warm start. The run began at thermal state fair, not nominal: the ten-minute cooldown of METHODOLOGY §5 was not achieved, so these are warm-start figures, the same deviation as station 01.
  2. Captured with the app. The PocketRoofline app redraws a live decode chart while each repeat runs; the harness that captured station 01 drew nothing during a repeat. GPU contention from that drawing is a possible confound, so a difference between this phone and station 01 cannot yet be put down to the silicon alone.
  3. The SILO step is unexplained. Decode fell from 59.17 tok/s in the last LISO repeat to 29.69 tok/s in the first SILO repeat, seconds later, with the thermal state serious on both sides, while prefill rose from 429 to 465 tok/s (over 2048- and 128-token prompts). A plain thermal slowdown would have pulled prefill down too, and nothing recorded here explains the step. A cold-start run with SILO first is owed. Until it exists, no peak-to-sustained percentage is quoted for this phone, and its SILO figures are not a sustained-throughput estimate.
